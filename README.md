# ORNL Interview Seminar: Transferable Basin and River-Network Representations

Muhammad Talha · Interview Seminar, Computational Sciences & Engineering Division, ORNL · November 9, 2026

A 47-slide reveal.js deck (about 45 minutes) styled after the comprehensive-exam deck. Everything runs offline: reveal.js 5.1.0, KaTeX 0.16.11 and Montserrat are vendored, and every image is stored in `assets/img/`.

## Run it

Opening `index.html` directly in a browser works. A local server is more reliable for presenter view:

```bash
cd ORNL_Seminar
python3 tools/serve.py 8000        # or: npm run serve  (no-cache server)
# then open http://localhost:8000/
```

Keys:

| Key | Action |
| --- | --- |
| → / Space | next slide or fragment |
| S | presenter view (notes, next slide, timer) in a second window; allow pop-ups |
| F | fullscreen |
| Esc / O | slide overview |
| B or . | black screen |

Slides are 1920×1080 logical pixels and scale to fit any screen. The first key press or click switches the browser to full screen, and on screens that aren't 16:9 the margin is filled with the slide's own colours (green title bar to the screen edge), so there are no letterbox bars.

**Builds and motion.** Most slides build step by step on each click, PowerPoint-style: figures wipe in panel by panel, cards slide in, and conclusions reveal "Next Challenge" last. On top of that:
- headline numbers count up
- the key-result bar chart (slide 33) grows, then shows what losing the gauge costs as dashed ghost bars
- the river-network schematic animates water flowing to the outlet
- the GNN diagram (slide 31) builds stage by stage, with messages moving along graph edges

The speaker notes mark every click with `[click]`. In `?print-pdf` all motion is switched off and every build is shown in full.

## Export the PDF backup

**Browser (no tools needed).** Open `http://localhost:8000/?print-pdf` in Chrome or Chromium, then Print → Destination "Save as PDF", Layout Landscape, Margins None, **Background graphics on**. Each slide becomes one page, with all fragments shown.

**Scripted (same result).**

```bash
npm install && npx playwright install chromium
npm run serve &            # in another terminal
npm run pdf                # writes ORNL_Seminar_Talha.pdf
npm run render             # PNG of every slide in renders/, plus a layout check
```

`tools/render_slides.mjs` flags elements that leave the slide or overflow their cards, images that fail to load, and speaker-note word counts.

## Figures built from data

- **Gauge-gap map (slide 6):** `tools/make_us_map.py` draws the real CONUS river network from the USGS National Atlas 1:1M hydrography (675,796 stream segments, line width scaled by Strahler order), plus the 9,536 active USGS stream gauges that report daily discharge (USGS NWIS site service, retrieved Nov 2026). It uses an Albers equal-area projection. Download links are in the script's docstring. The gauges are a separate transparent layer, so they fade in on the "~12k" click.
- **Lumped vs. distributed figures (slide 12):** `tools/make_concept_figs.py` generates the illustrative basin, gridded fields and stream network.
- **Model families (slide 8)** uses the three diagrams you supplied (`assets/img/model_*.png`) with live HTML text. **Data Types (slide 10)** is drawn as inline SVG with live HTML text.

## Editing notes

- Build classes: `fragment` with `fade-up`, `fade-left`, `fade-right`, `zoom-in` or `wipe`; `enter` / `enter-fade` (with `style="--d:.2s"` for delay) animate when the slide appears; `data-count="…"` makes a number count up; `data-network` inlines the animated river schematic (`js/network.js`, generated by `tools/make_network_svg.py`).
- The two generalization tests always use `<span class="test t">` (blue, clock icon) for temporal and `<span class="test s">` (amber, pin icon) for spatial.
- One visible placeholder remains: the variable count on slide 20 (`[TODO: count]`). The BASINGRID PDF supplied was corrupted, so that number could not be checked.
- Part 4 deliberately leaves out the comparison against TVA's operational forecasts and any TVA-internal data. NWM is the only operational reference.
